## Route Ordering Comparison

This benchmark compares three route-ordering strategies inside the day-ahead mixed-fleet hub-and-spoke pipeline:

- `nearest_neighbor` heuristic
- pretrained attention decoder from `pretrained/tsp_20`
- transit-specific learned route-ordering model trained on 2-opt-improved synthetic routes

The benchmark was run on 20 synthetic instances generated by the same clustered-demand procedure used for pipeline validation.

### Setup

- number of instances: `20`
- base seed: `1234`
- number of hubs: `3`
- fleet: feeder and trunk mix as defined in the transit pipeline

### Aggregate Results

| Metric | Heuristic | Attention | Learned |
|---|---:|---:|---:|
| Mean total route length | 0.867255 | 1.014257 | 0.828558 |
| Mean delta vs heuristic | - | 0.147002 | -0.038697 |
| Mean delta % vs heuristic | - | 17.192% | -4.354% |
| Median delta | - | 0.152323 | - |
| Wins vs heuristic | 20 | 0 | 17 |
| Losses vs heuristic | 0 | 20 | 3 |

### Interpretation

Observed behavior:

- the pretrained TSP attention decoder is consistently worse than the heuristic in this transit setting
- the transit-specific learned model improves over the heuristic on average
- the learned model also beats the heuristic on 17 out of 20 benchmark instances
- the learned model still leaves room to improve toward the 2-opt oracle labels used for supervision

Conclusion:

- the pretrained TSP attention model should remain only a fallback reference baseline
- the learned transit-specific orderer is the better default route-ordering component for the current pipeline
- the training signal should be refined further if the goal is to close the remaining gap to the 2-opt-improved target

## Full Pipeline Metrics

The learned orderer is now the default route-construction strategy in the day-ahead pipeline. We also
benchmarked the full transit pipeline metrics, not just route ordering.

### Batch benchmark

Benchmark command:

```bash
python -m transit.benchmark_pipeline_metrics --instances 10 --base-seed 1234 --num-hubs 3
```

Results:

| Strategy | Mean route length | Mean utilization | Mean route utilization | Mean route count |
|---|---:|---:|---:|---:|
| Heuristic | 0.889041 | 0.701506 | 0.746486 | 4.3 |
| Attention | 0.973619 | 0.701506 | 0.746486 | 4.3 |
| Learned | 0.827686 | 0.701506 | 0.746486 | 4.3 |

Interpretation:

- utilization is unchanged because fleet assignment is held constant
- route length improves when moving from heuristic to learned ordering
- the learned ordering is the best default route-construction module for the current system

### Custom instance benchmark

Custom instance generation command:

```bash
python -m transit.custom_instance --output /tmp/custom_transit_instance.json --seed 2026 --num-clusters 4 --requests-per-cluster 10 --cluster-spread 0.018
```

Benchmark command:

```bash
python -m transit.benchmark_pipeline_metrics --instance-json /tmp/custom_transit_instance.json
```

Results:

| Strategy | Total route length | Utilization | Mean route utilization | Route count |
|---|---:|---:|---:|---:|
| Heuristic | 1.024704 | 0.750000 | 0.773333 | 5 |
| Attention | 1.021507 | 0.750000 | 0.773333 | 5 |
| Learned | 0.913460 | 0.750000 | 0.773333 | 5 |

Interpretation:

- the learned route orderer remains the strongest choice on the custom transit scenario
- the attention baseline is close to heuristic on this single case, but still not consistently better in aggregate
- the learned model is the best default route-ordering component for the current transit pipeline

## Joint Planner Benchmark

The learned hub-selection and fleet-assignment modules were trained as a joint planner and evaluated
on the same synthetic transit benchmark.

### Batch benchmark

Benchmark command:

```bash
python -m transit.benchmark_joint_planner --instances 20 --base-seed 1234 --num-hubs 3 --joint-policy-path outputs/transit_joint_policy.pt --learned-order-path outputs/transit_orderer.pt
```

Results:

| Strategy | Mean route length | Mean utilization |
|---|---:|---:|
| Heuristic | 0.901793 | 0.697544 |
| Learned route order only | 0.835070 | 0.697544 |
| Joint learned hub + fleet + order | 1.075017 | 0.723439 |

### Custom instance benchmark

Benchmark command:

```bash
python -m transit.custom_instance --output /tmp/custom_transit_instance.json --seed 2026 --num-clusters 4 --requests-per-cluster 10 --cluster-spread 0.018
python -m transit.benchmark_joint_planner --instance-json /tmp/custom_transit_instance.json --joint-policy-path outputs/transit_joint_policy.pt --learned-order-path outputs/transit_orderer.pt
```

Results:

| Strategy | Total route length | Utilization |
|---|---:|---:|
| Heuristic | 1.024704 | 0.750000 |
| Learned route order only | 0.913460 | 0.750000 |
| Joint learned hub + fleet + order | 0.925462 | 0.750000 |

Interpretation:

- the joint planner is functionally correct and demand-safe
- it improves utilization in the batch benchmark
- it remains slightly worse than the learned-order-only model on route length
- it is therefore a valid prototype, but not yet the best-performing version of the system
